# 需求访谈记录

产品需求以 requirements.md 为准；本文保留确认过程。


### 第一轮

- 已确认：团队内部使用，集中放常用系统和工具。
- 已确认：原始表述“分配”指分类，例如开发工具、运营系统、常用文档。
- 已确认：管理员登录后维护卡片，其他人只浏览。

### 第二轮

- 已确认：浏览不用登录，只有管理时登录。
- 已确认：一张卡片可以属于多个分类。
- 已确认：预计卡片数量为几十张以内。
- 尚未确认：部署在内网还是其他环境；免登录浏览不等于已确定向公网开放。

### 第三轮

- 已确认：左侧分类栏、右侧展示卡片，默认全部。
- 已确认：管理员使用 Markdown 源码编辑，同时预览效果，并有加粗、列表等工具按钮。
- 已确认：卡片显示简短预览，另设“查看说明”入口展示完整 Markdown。
- 采用用户选中的筛选方案：全部视图不重复展示多分类卡片。

### 第四轮

- 已确认：点击卡片后在新标签页打开目标系统，保留导航网站。
- 已确认：第一版只要分类筛选，保持简单，不加入关键词搜索和管理员手动排序。
- 已确认：说明用弹窗，新增和编辑用右侧抽屉，保存后直接更新卡片。

### 第五轮

- 已确认：管理员登录接入 Microsoft Entra，参考 `/Users/jizhiyonggan/Documents/Code/device-manager-v3`，环境变量直接套用。
- 已确认：管理员可新增、改名、删除分类，每张卡片至少选择一个分类。
- 已确认：使用 Docker Compose 一起启动应用和 PostgreSQL。
- 后续修正：前端与 Go 后端合并为同一个应用镜像，打包方式参考 `database-platform`；PostgreSQL 为独立服务。

### 第六轮

- 已确认：有卡片关联的分类禁止删除，管理员先将卡片调整到其他分类，再删除空分类。

- 实现约束：后端在删除分类时检查关联关系；编辑卡片时校验至少保留一个分类，不能只依赖前端按钮限制。

- 已确认：支持浅色、深色两种主题，可以切换。
- 已确认：名称、链接、至少一个分类必填；描述可空；预览从描述自动生成。
- 已确认：分类按名称排序，卡片按创建时间倒序。

## 后续调整：访问权限

- 用户确认：项目强制登录后才能查看，普通用户只读，管理员可以编辑。
- 此要求取代第二轮的免登录浏览决定；退出或身份失效后返回登录页。

## 后续调整：个人工作台与卡片权限

- 概览去掉描述摘要与详细说明入口，卡片布局更紧凑。
- 每个人可独立收藏、拖拽排序，收藏卡片始终位于前面，保存到数据库。
- 卡片分为内部公开与私有；内部公开对登录用户可见，管理员维护。
- 普通用户可创建和维护自己的私有卡片，分享给指定团队成员；普通接收者只读。
- 最终修正：管理员可以查看和维护所有人的公开、私有卡片。
- 实施约定：管理员新建默认内部公开，普通用户新建为私有；分享选择已登录过本站的成员，取消勾选并保存可撤销。
- 拖拽使用第三方 dnd-kit；根据卡顿反馈修复卡片原有 transform 动画与拖拽的冲突。
