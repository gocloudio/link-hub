# 团队导航需求说明

版本：v1.3。状态：补充个人收藏、排序、私有卡片与指定成员分享；普通用户也可创建和维护内部公开卡片（本人创建的卡片由创建者维护），管理员可管理全部卡片。

页面名称为“团队导航”，项目目录保留 `link-hub`。下文区分用户已确认的产品需求与为实现需求提出的技术建议。

## 1. 目标与使用对象

为内部团队提供一个集中访问常用系统和工具的导航网站，规模为几十张卡片以内。用户打开页面、选择分类、点击卡片，即可在新标签页访问目标系统。

所有用户通过 Microsoft Entra 登录后才能查看内容；普通用户维护自己创建的公开与私有卡片，他人维护的公开卡片和收到的分享只读；管理员可维护所有人的公开和私有卡片。电脑与手机均须支持浏览和管理。

## 2. 首期范围

### 2.1 单页浏览

- 桌面端左侧为分类栏，右侧为卡片区，默认选择“全部”。
- 一张卡片可以属于多个分类，但在“全部”视图中只出现一次。
- 点击一个分类，显示关联该分类的卡片；切换“全部”恢复完整列表。
- 提供分类筛选、个人收藏与拖拽排序，不提供卡片关键词搜索。
- 分类按名称排序；卡片优先显示个人收藏，其次遵循个人手动顺序，尚未排序的卡片按创建时间倒序。编辑卡片不改变排序。
- 概览卡片包含名称、分类、目标链接、私有标记、收藏按钮及拖拽手柄。
- 概览不显示描述预览，采用紧凑布局。Markdown 描述通过说明弹窗阅读，在编辑抽屉编辑和预览。
- 点击卡片主要区域，在新标签页打开目标链接，原导航页保留。
- 分类标签右侧保留“查看说明”按钮，点击后以弹窗展示完整 Markdown；所有能查看卡片的用户均可使用。
- 收藏、拖拽、编辑、删除使用独立按钮，不触发目标链接跳转。

### 2.2 卡片维护

- 管理员可以新增、编辑、删除任何公开或私有卡片；普通用户可以新增、编辑、删除自己的公开与私有卡片。
- 新增和编辑均使用右侧抽屉；保存成功后更新当前页面，不进入独立管理页。
- 编辑器采用 Markdown 源码与实时预览，带加粗、列表等工具按钮。
- 每张卡片至少选择一个分类，支持多选。
- 名称、链接及至少一个分类必填；描述可以为空。
- 建议删除卡片前展示确认提示；删除卡片同时清理其分类关联，不删除分类。

### 2.3 分类维护

- 管理员可以新增、改名和删除分类。
- 有卡片关联的分类禁止删除，提示先调整这些卡片的分类。
- 管理员先把卡片调整到其他分类，确保每张卡片仍至少有一个分类，再删除空分类。
- 即使相关卡片还有其他分类，只要当前分类仍有关联，就禁止直接删除。
- 分类管理在主页面内完成；具体使用弹窗或抽屉由实现时统一交互规范。

### 2.4 Markdown 范围

- 支持文字排版（包括工具栏加粗）、列表、链接、行内代码与代码块。
- 不提供图片展示或图片上传，不提供图片工具按钮。
- Markdown 的源码与预览保留在编辑抽屉中。
- 实现要求：不执行描述中的 HTML 或脚本，手动粘贴的图片语法也不能绕过首期内容限制。
- 概览不渲染 Markdown，也不展示说明摘要。
- 代码块过长时在代码块内部滚动，不撑宽卡片或手机页面。

### 2.5 手机端

- 分类栏可收起，入口应能显示当前分类，切换分类操作适合触屏。
- 卡片单列排列。
- 支持通过手柄长按拖拽排序，手柄以外仍可正常滚动页面。
- 新增和编辑仍沿用抽屉交互，在小屏占满可用宽度；表单、分类多选、保存和取消均可用。
- Markdown 源码与预览在手机上允许上下排列，保证输入和阅读空间。
- 手机支持分类维护、卡片新增、编辑、删除和 Entra 登录。

### 2.6 主题与显示

- 页面名称为“团队导航”。
- 支持浅色、深色两种主题，登录后可切换。
- 主页面、分类栏、卡片、编辑抽屉、Markdown 编辑器与预览均适配两种主题。
- 实施约定：首次访问跟随系统主题，用户主动选择后在当前浏览器保存偏好。
- 字体、具体颜色和视觉细节在页面设计阶段确定，遵循已确认的布局与主题能力；没有要求复刻 rebalancer 的视觉风格。

## 3. 权限与身份

| 能力 | 未登录访客 | 已登录但无管理员角色 | Entra 管理员 |
| --- | --- | --- | --- |
| 浏览分类与卡片 | 禁止 | 公开、本人私有、获分享的私有卡片 | 全部卡片 |
| 打开有权访问的卡片链接 | 禁止 | 允许 | 允许 |
| 维护内部公开卡片 | 禁止 | 仅本人创建的 | 全部 |
| 维护本人私有卡片 | 禁止 | 允许 | 允许 |
| 维护他人私有卡片 | 禁止 | 禁止 | 允许 |
| 个人收藏与排序 | 禁止 | 允许 | 允许 |
| 新增、改名、删除分类 | 禁止 | 禁止 | 允许 |

- Entra 实现及环境变量直接参考 `device-manager-v3`。
- 前端使用 MSAL 获取 access token；Go 后端校验签名、有效期、租户、audience、scope 和管理员角色。
- 按“直接套用”解释，管理员角色沿用原项目的 `ENTRA_ADMIN_ROLE`，原项目默认值为 `dm.admin`；scope 默认值为 `dm.access`。实际接入以原项目配置值为准。
- 所有管理写操作均由后端授权；隐藏按钮不能代替权限校验。
- 未登录显示登录页，不加载分类与卡片；所有业务接口要求有效登录。
- 登录页发起 Entra 登录，成功后进入导航页；退出登录或身份失效后立即隐藏内容并返回登录页。
- 会话过期或权限不足时不保存写操作，给出明确反馈并保留尚未提交的输入，允许重新登录后再提交。
- 首期无本地账号、注册、密码管理或站内角色分配功能。

### 3.1 私有与分享

- 内部公开卡片对所有登录用户可见，由创建者和管理员维护；既有卡片迁移后保持内部公开。
- 所有用户新增入口为“添加卡片”；管理员新增默认内部公开，普通用户新增默认私有，均可切换可见范围。
- 私有卡片对创建者、指定分享成员以及管理员可见。普通分享接收者只读；管理员可以查看、编辑、分享、删除所有公开与私有卡片，编辑后保留原创建者。
- 分享通过编辑抽屉选择已登录过本站的成员，最多 100 人。名单来自本站记录的 Entra 身份，不要求 Graph 客户端密钥。
- 取消分享并保存后，后端立即拒绝对方的卡片读取、收藏及排序请求；列表和个人偏好不再返回该卡片。已打开页面在刷新或再次聚焦时同步。
- 卡片详情、列表、分类计数、收藏和排序均须遵循可见性权限，不能仅依靠隐藏前端元素。

### 3.2 个人收藏与排序

- 每个登录用户独立收藏和排序，保存到 PostgreSQL，以 Entra 用户对象 ID 隔离；不可指定或修改其他人的偏好。
- 收藏始终置顶，收藏与未收藏卡片分别在各自区域内拖拽排序。
- 支持鼠标、触屏手柄长按、键盘空格与方向键操作。
- 分类筛选时只移动当前可见卡片对应的位置，隐藏卡片保持原位；顺序为跨分类的个人全局顺序。
- 有手动顺序时，新出现的卡片在同一收藏分组的手动顺序之后，按创建时间倒序展示。
- 保存失败回滚本次排序或收藏变更并提示重试；删除卡片时级联清除其收藏、排序和分享关系。

## 4. 内容字段与数据关系

以下为实现建议，字段命名可在接口设计时统一，业务规则不得改变。

| 实体 | 主要字段 | 规则 |
| --- | --- | --- |
| 卡片 cards | id、name、description_markdown、url、is_private、owner_id、created_at、updated_at | 默认内部公开；私有卡片保留创建者身份；更新时间不参与排序 |
| 分类 categories | id、name、created_at、updated_at | 管理员维护；有关联卡片时禁止删除 |
| 个人偏好 user_card_preferences | user_id、card_id、favorite、position | 收藏与顺序独立更新，只能操作自己可见的卡片 |
| 团队成员 members | id、name、username | 登录时记录 Entra 对象 ID 与显示信息，供指定成员分享 |
| 分享 card_shares | card_id、user_id | 私有卡片的只读分享名单 |
| 关联 card_categories | card_id、category_id | 多对多；同一关联不重复；每张卡片至少关联一个分类 |

- 卡片与分类关系存入 PostgreSQL，更新卡片和关联关系使用同一事务。
- 数据库以外键和唯一约束维护关联一致性；后端事务保证“至少一个分类”和“有关联不允许删除”的规则，包括并发操作。
- 默认排序在后端统一执行；同一创建时间的卡片使用稳定的次级排序，避免页面刷新后顺序随机变化。
- 删除卡片可清理关联记录；删除分类不允许级联删除卡片。
- 建议卡片目标链接仅接受完整 HTTP/HTTPS URL，兼容内网域名、IP、端口、路径和查询参数；不主动访问目标系统验证连通性。
- 首次部署没有业务内容，由管理员创建分类和卡片。真实初始链接尚未提供。

## 5. 技术方案与工程参考

| 项目部分 | 约束或方案 | 参考 |

接口按能力划分为：用户可见的分类与卡片、成员查询、个人收藏与顺序、卡片增删改、管理员分类增删改。ConnectRPC 校验登录和分类管理权限，数据库事务内校验卡片所有者、分享及管理员权限。

## 6. 打包、配置与部署

### 6.1 一个应用镜像

- 多阶段 Dockerfile：构建前端静态产物、编译 Go 服务，再把两者放入最终应用镜像。
- 由一个 Go 服务同时提供页面和 RPC 接口，浏览器通过同一来源访问。
- 正式运行不依赖 Vite 开发服务器。
- Docker Compose 启动 `app` 和 `postgres` 两个服务；数据库独立容器，使用持久化数据卷。
- 首次启动执行数据库迁移；重复启动不清空数据。提供应用和数据库健康检查。
- 部署域名、访问端口、网络范围和实际 PostgreSQL 凭据在部署阶段确定。

### 6.2 Entra 配置复用

| 环境变量 | 用途 |
| --- | --- |
| AUTH_MODE / VITE_AUTH_MODE | Entra 登录模式 |
| ENTRA_TENANT_ID / VITE_ENTRA_TENANT_ID | 同一租户 ID |
| ENTRA_CLIENT_ID / VITE_ENTRA_CLIENT_ID | 前端 SPA 应用 ID |
| ENTRA_AUDIENCE | 后端 API 的 audience |
| ENTRA_REQUIRED_SCOPE | 后端要求的短 scope，原项目默认为 dm.access |
| VITE_ENTRA_API_SCOPE | 前端请求的完整 API scope |
| ENTRA_ADMIN_ROLE | 后端识别的管理员角色，原项目默认为 dm.admin |

- 按用户要求复用 `device-manager-v3` 中这些变量及配置值；只复制相关字段，不复制其数据库和其他业务配置。
- 为适配单镜像，建议参考 `database-platform`，由 Go 在运行时提供前端需要的公开 Entra 配置；保留原有变量名，修改环境配置后不必重新编译前端。
- 仅公开租户、SPA 应用 ID 和 scope 等前端登录必要配置；本站登录流程不需要 Graph 用户查询或客户端密钥。
- 已复用环境配置并验证过真实 Entra 登录；部署新域名时仍需核对回调地址。
- PostgreSQL 的配置单独定义，以 `DATABASE_URL` 注入 Go 服务；不得沿用其他项目的数据库地址。

## 7. 关键状态与反馈

| 状态 | 预期行为 |
| --- | --- |
| 首次访问、数据加载中 | 显示加载状态，避免把加载过程显示成空列表 |
| 没有可见卡片 | 成员和管理员均可添加公开或私有卡片 |
| 当前分类为空 | 提示当前分类暂无卡片，可切回“全部” |
| 没有分类时新增卡片 | 引导管理员先创建分类，禁止保存无分类卡片 |
| 获取数据失败 | 显示错误和重试入口，不以假数据替代 |
| 表单校验失败 | 指明出错字段，保留已填写内容 |
| 正在保存 | 防止重复提交；成功后更新卡片及分类关联显示 |
| 保存失败 | 保留输入，允许重试 |
| 已有内容被其他管理员删除 | 明确提示记录不存在，刷新相关列表 |
| 删除被引用的分类 | 拒绝操作，提示先调整关联卡片 |
| Entra 登录取消或失败 | 停留登录页，不显示团队数据，允许重新尝试登录 |
| 内容超长或手机窄屏 | 文本合理换行，编辑区域可滚动 |

## 8. 首期验收标准

以下为当前版本验收要求。

1. 未登录用户只能看到登录页，不能读取分类、卡片或说明；普通用户登录后可浏览、筛选和打开有访问权限的卡片，并维护自己创建的公开或私有卡片与个人偏好。
2. 多分类卡片在“全部”中不重复，在各自分类筛选结果中均可找到。
3. 点击卡片在新标签页打开；收藏、拖拽、编辑和删除不会误触目标跳转。
4. Entra 管理员可维护任何公开/私有卡片及分类；普通用户只能维护自己创建的公开或私有卡片和个人偏好。
5. 新增或编辑使用右侧抽屉，保存后当前页面显示正确内容。
6. Markdown 编辑器具备源码、实时预览、格式工具栏；编辑预览支持文字、列表、链接和代码，不加载图片；概览分类右侧提供“查看说明”入口。
7. 卡片无法保存为零分类；有关联的分类无法删除，解除全部关联后可以删除。
8. 手机端分类栏可收起、卡片单列，全部浏览与管理功能可操作。
9. 同一应用镜像提供页面与 RPC，Compose 可启动应用和 PostgreSQL；容器重建后业务数据仍保留。
10. 页面没有卡片搜索、图片上传或独立管理页面；分享名单支持按姓名和账号筛选。
11. 分类按名称排序；个人收藏置顶、拖拽顺序保存并跨设备生效；编辑卡片不改变顺序。
12. 名称、链接或分类缺失时不能保存；描述为空可以保存，概览不显示描述。
13. 电脑和手机均可切换浅深色主题，Markdown 编辑与预览显示一致，主题偏好可保留。
